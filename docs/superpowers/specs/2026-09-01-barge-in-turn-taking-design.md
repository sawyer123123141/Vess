# Vess Barge-In and Natural Turn-Taking Design

**Status:** Approved architecture, pending implementation plan.

## Goal

Let a person interrupt Vess naturally while Vess is speaking, without allowing Vess's own speaker output, incidental noise, or short false starts to corrupt the conversation state.

The target interaction is:

1. Vess is speaking.
2. The microphone remains active.
3. Near-end human speech is detected despite speaker playback.
4. Vess pauses quickly.
5. The overlapping human utterance continues to be captured and transcribed.
6. If the interruption is real, the old response is cancelled and the new utterance becomes the latest conversational intent.
7. If the interruption was false and no real user utterance materializes, Vess resumes the interrupted waveform instead of silently abandoning the response.
8. Conversation memory records what was actually delivered, not merely what the LLM generated.

This feature must preserve the existing independent render loop, newest-intent generation semantics, one-clause-ahead TTS pipeline, and local-only architecture.

## Non-Goals

This design does not add:

- a new LLM
- long-term memory
- a learned interruption classifier
- a mandatory acoustic echo-cancellation implementation chosen without hardware testing
- multi-speaker diarization
- semantic backchannel classification
- continuous self-reflection
- full duplex speech where Vess deliberately talks over a person
- perfect word-level alignment between TTS audio and text

## Existing Constraints

The current implementation has four relevant properties:

1. `AudioLoop` discards microphone blocks while `state.speaking` is true.
2. `VoiceOutput` uses blocking playback and generation freshness only prevents future stale speech; it cannot interrupt a waveform already being played.
3. `ConversationWorker.submit()` creates a newer generation and therefore invalidates older queued/generated work, but there is no explicit cancellation operation that does not also create a replacement request.
4. Short-term conversation memory is currently finalized from clauses generated by the LLM rather than clauses proven to have finished playback.

Barge-in must correct all four without merging audio, cognition, output, and rendering into one synchronous loop.

## Core Architecture

The runtime remains asynchronous and event-driven.

```text
microphone
   |
   v
CapturedAudioBlock
   |
   v
CapturePreprocessor  <----- RenderReference from AudioPlayer
   |
   v
UtteranceAssembler / VAD
   |
   +--------------------------+
   | Vess silent              | Vess speaking
   v                          v
normal wake/follow-up     InterruptionDetector
                               |
                               v
                         TurnCoordinator
                          /           \
                         /             \
               false interruption     real interruption
                    resume              commit
                         \             /
                          v           v
                         VoiceOutput + ConversationWorker
```

The key separation is that acoustic detection does not own conversation generations, and `VoiceOutput` does not decide whether microphone audio is a real user turn. `TurnCoordinator` is the narrow policy layer connecting those two worlds.

## 1. Captured Audio Stays Live During Speech

When barge-in is enabled, `AudioLoop` must no longer discard all microphone blocks merely because `state.speaking` is true.

The capture callback remains minimal and non-blocking. It copies microphone samples into the existing capture queue and preserves timing metadata when available.

Introduce a lightweight captured-block value such as:

```python
@dataclass(frozen=True)
class CapturedAudioBlock:
    samples: np.ndarray
    adc_time: float | None
    received_at: float
```

`adc_time` comes from the audio backend when available. It is retained because real echo cancellation and latency analysis benefit from knowing capture timing. Tests may use `None`.

When barge-in is disabled, current behavior may remain conservative: microphone audio during Vess speech may be ignored. This makes the feature safely roll-outable.

## 2. Capture Preprocessing and Echo-Cancellation Seam

Speaker playback can re-enter the microphone and look exactly like speech to an ordinary VAD. Do not solve this permanently with a hand-built amplitude threshold or simple waveform correlation.

Add a preprocessing boundary:

```python
class CapturePreprocessor(Protocol):
    def process(self, block: CapturedAudioBlock) -> np.ndarray:
        ...
```

A passthrough implementation is sufficient for CI and non-speaker test setups.

The architecture must also expose Vess's rendered output as a `RenderReference` stream to preprocessors that need it. A future real backend may use WebRTC AEC3 or another local acoustic echo-cancellation implementation selected after target-PC testing.

Requirements:

- no heavy DSP work in the PortAudio/sounddevice real-time callback
- no network service requirement
- no mandatory CUDA dependency
- preprocessing failures must degrade in a visible, configurable way rather than silently pretending echo suppression succeeded
- live barge-in with speakers must not be declared production-ready until self-echo tests pass on the actual hardware

The first implementation may provide only the seam plus a passthrough backend. `barge_in.enabled` remains false by default until hardware acceptance.

## 3. Interruption Detection

`InterruptionDetector` answers one narrow question:

> Is there sustained near-end speech while Vess is currently speaking?

It consumes preprocessed microphone audio and does not know about LLMs, TTS queues, memory, or prompts.

V1 uses deterministic duration-based detection on top of the existing VAD/utterance assembly rather than introducing another ML model.

Configuration includes a conservative starting minimum speech duration of 0.5 seconds. This is explicitly tunable during hardware acceptance.

A short spike, click, cough-like burst, or one isolated block must not immediately commit an interruption.

The detector emits an interruption **candidate** once its minimum duration is satisfied.

## 4. Two-Phase Interruption Semantics

An acoustic candidate must not immediately and irreversibly destroy the current response.

Use a two-phase protocol:

### Phase A: Pause

When an interruption candidate is detected:

1. `TurnCoordinator` marks an interruption as pending.
2. `VoiceOutput.pause_for_interruption()` aborts audible playback quickly and saves enough playback state to resume the same waveform.
3. The current LLM generation is **not cancelled yet**.
4. Future playback is held while the interruption is pending.
5. Microphone capture and utterance assembly continue until the overlapping human speech finishes.
6. The face leaves speaking behavior and enters listening behavior while the candidate is active.

The TTS synthesis worker may finish at most the existing bounded one-clause-ahead work while playback is paused. It must not grow an unbounded backlog.

### Phase B1: Commit Real Interruption

If the captured utterance produces a non-empty accepted transcript:

1. `TurnCoordinator` commits the interruption.
2. `ConversationWorker.cancel_active_response(reason="barge_in")` invalidates the old generation without creating a new request.
3. `VoiceOutput.commit_interruption()` discards the saved remainder and every stale prepared/queued clause from the cancelled generation.
4. The accepted transcript is submitted as a fresh generation.
5. Existing newest-intent logic continues to control any later request races.

The cancel operation must be monotonic: generation identifiers are never reused or moved backward.

True cancellation of the underlying Ollama HTTP/inference request is not required in V1. The old stream must stop contributing clauses as soon as the worker observes that its generation is stale and must close its response promptly afterward.

### Phase B2: Roll Back False Interruption

If the interruption candidate times out without producing a real transcript:

1. no new conversation generation is created
2. the existing generation remains current
3. `VoiceOutput.resume_after_false_interruption()` resumes the interrupted waveform from its saved playback position
4. speaking/performance state is restored when resumed audio physically starts
5. the event is logged as a false interruption

The timeout is configurable. The initial design default is 2.0 seconds, matching a conservative production precedent; target-PC testing may reduce it if it feels sluggish.

V1 does not attempt to classify semantic backchannels such as "mhm" or "right" as non-interrupting. That requires actual usage data or a dedicated policy. A non-empty transcript is treated as a real user turn.

## 5. Streaming Cancellable AudioPlayer

The high-level `sounddevice.play()` / `wait()` helper is not a sufficient long-term playback boundary because it hides useful cursor and render-reference information.

Introduce an `AudioPlayer` abstraction owned by `VoiceOutput`.

Conceptual interface:

```python
@dataclass(frozen=True)
class PlaybackReceipt:
    status: str                 # completed | paused | interrupted | error
    frames_started: int
    frames_completed: int
    total_frames: int
    sample_rate: int

class AudioPlayer(Protocol):
    def play(self, audio: np.ndarray, sample_rate: int) -> PlaybackReceipt:
        ...

    def pause_for_interruption(self) -> PlaybackReceipt | None:
        ...

    def resume(self) -> PlaybackReceipt:
        ...

    def discard_paused(self) -> None:
        ...
```

The production implementation uses a stream-oriented sounddevice/PortAudio path that can terminate pending output immediately with abort semantics rather than waiting for queued device buffers to drain.

The player owns:

- current waveform
- sample rate
- playback cursor / completed-frame estimate
- paused remainder
- current playback identity
- render-reference publication

`VoiceOutput` continues to own clause ordering, generation freshness, performance cues, edge trimming, and synthesis.

The real-time audio callback must remain minimal. It must not write files, call the LLM, append database events, perform model inference, or block on ordinary locks with unpredictable duration.

A small amount of replay at the resume boundary is preferable to skipping speech. Hardware testing decides whether a safety overlap is needed to account for device buffering.

## 6. VoiceOutput Interruption Behavior

Add explicit methods to `VoiceOutput`:

```python
pause_for_interruption()
commit_interruption(generation_id)
resume_after_false_interruption()
```

`pause_for_interruption()`:

- is idempotent
- affects only the currently audible generation
- clears active performance state when sound stops
- prevents the playback worker from advancing to the next clause while pending
- records pause latency and playback position

`commit_interruption()`:

- permanently discards the paused remainder
- relies on generation freshness to discard queued/prepared stale work
- never resumes stale audio

`resume_after_false_interruption()`:

- is legal only while an interruption is pending and the generation is still current
- resumes the same waveform rather than resynthesizing it
- restores the original `PerformanceCue` when physical playback resumes
- then allows normal playback of subsequent clauses from the same generation

The existing one-ready-waveform-ahead bound remains intact.

## 7. Conversation Cancellation Without Submission

Add a `ConversationWorker.cancel_active_response(reason)` operation.

It must:

- advance the latest-generation token atomically
- invalidate current generated/future TTS for the old generation
- not enqueue an empty or synthetic user request
- preserve any separate pending user request correctly
- record why the generation was cancelled
- be safe if there is no active response

A later `submit(transcript)` allocates another newer generation normally.

Cancellation and submission are deliberately distinct operations so acoustic barge-in does not have to wait for Whisper before stale response generation is invalidated.

Under the two-phase protocol, cancellation happens only on committed real interruption, not on the initial pause candidate.

## 8. Delivery-Aware Conversation Memory

Generated text is not equivalent to heard text.

Replace the current "collect every generated clause and remember it at LLM completion" rule with a delivery ledger keyed by generation.

Each generation tracks at least:

- user request
- generated clauses
- clauses that fully completed physical playback
- currently interrupted clause, if any
- whether LLM generation completed
- whether the turn completed normally or was interrupted

Extend short-term turn representation so interrupted turns are explicit rather than disguised as complete turns.

Conceptually:

```python
@dataclass(frozen=True)
class ConversationTurn:
    timestamp: float
    user: str
    assistant: str
    status: str = "completed"       # completed | interrupted
    interrupted_clause: str | None = None
```

For a completed response, `assistant` contains the physically completed clauses.

For a real interruption:

- `assistant` contains only clauses that fully completed playback
- `status` is `interrupted`
- `interrupted_clause` may contain the clause that had begun playing, but prompt construction must explicitly treat it as partially delivered and must not assume the user heard the entire clause

If no complete clause was delivered before interruption, the user side of the turn is still retained with an empty `assistant` and `status="interrupted"` so the prior request does not vanish from short-term context.

The prompt builder may render an interrupted turn as:

```text
User: <prior request>
Vess (interrupted): <fully delivered text>
Vess had started another clause but it was interrupted; do not assume the user heard it.
```

No word-level claim is made about exactly how much of the interrupted clause was heard.

### Playback lifecycle events

Voice output must emit enough internal receipts for the ledger to distinguish:

- clause playback started
- clause playback completed
- clause paused for candidate interruption
- clause resumed
- clause interrupted/abandoned
- generation playback drained

These callbacks/events must be generation-scoped so stale playback cannot finalize memory for a newer turn.

## 9. TurnCoordinator

Introduce one small coordinator responsible for barge-in policy.

It owns the interruption state machine, not the audio model and not the conversation text.

Conceptual states:

```text
IDLE
AGENT_SPEAKING
INTERRUPTION_PENDING
```

Transitions:

```text
IDLE -> AGENT_SPEAKING
    when Vess physical playback starts

AGENT_SPEAKING -> INTERRUPTION_PENDING
    when InterruptionDetector emits a sustained-speech candidate

INTERRUPTION_PENDING -> IDLE/user-turn flow
    when a real transcript commits the interruption

INTERRUPTION_PENDING -> AGENT_SPEAKING
    when the false-interruption timeout expires without a real transcript
```

The coordinator must make duplicate candidate events harmless.

It must not hold the central `State` lock while calling potentially blocking audio, transcription, TTS, or conversation operations.

## 10. Runtime State Semantics

`State` remains the authoritative public runtime state.

Important semantic rule:

- `state.listening` means Vess is meaningfully attending to a human turn/candidate, not merely that raw microphone energy exists.
- raw VAD status during speaker playback belongs in diagnostics until echo preprocessing says it is credible near-end speech.

During a pending interruption:

- `speaking = False` once audio is actually paused
- `listening = True`
- transient performance returns to neutral

On false-interruption resume:

- `listening = False`
- `speaking = True` only when resumed audio physically starts
- the clause's original performance cue becomes active again at that same physical start point

This preserves the existing face priority semantics without making self-echo look like attentive listening.

## 11. Wake and Follow-Up Semantics

A barge-in transcript while Vess is speaking is automatically considered part of the active conversation. It does not require the wake phrase.

Normal wake matching still applies when Vess is idle and the conversation window has expired.

An interruption transcript is submitted only after the interruption is committed. The acoustic candidate itself never becomes a synthetic text request.

## 12. Error Handling

### Audio player cannot pause/abort

- record `barge_in_pause_error`
- do not claim interruption succeeded
- continue capturing the human utterance
- when transcript arrives, cancel the old generation so no additional clauses begin after the current blocking audio returns
- expose this failure in diagnostics

### Capture preprocessor fails

- record the failure
- if configured policy is `disable_on_preprocessor_error`, disable live barge-in for the session rather than passing self-echo through as trustworthy speech
- ordinary idle microphone/wake handling remains usable if raw capture itself still works

### Whisper returns no transcript

- treat the candidate as false after the configured timeout
- resume only if the original generation is still current
- if some other request has superseded it, discard the paused remainder instead

### New request arrives during pending interruption

Newest-intent semantics win. The old paused response must never resume after a newer generation exists.

### Shutdown during pause

Close/abort the player, discard paused waveform state, clear speaking/listening/performance state, and let existing worker shutdown proceed without waiting for false-interruption timeout.

## 13. Configuration

Add a barge-in block with conservative defaults:

```json
{
  "barge_in": {
    "enabled": false,
    "min_speech_seconds": 0.5,
    "false_interruption_timeout_seconds": 2.0,
    "preprocessor": "passthrough",
    "disable_on_preprocessor_error": true
  }
}
```

`enabled` stays false until target-PC acceptance proves the selected preprocessing path prevents self-echo interruptions with the intended microphone and speakers.

No tuning value in this block is considered final before hardware testing.

## 14. Diagnostics and Evaluation

Add generation-scoped debug/event measurements for:

- interruption candidate timestamp
- playback pause requested timestamp
- playback physically paused timestamp
- speech-start-to-pause latency
- playback frame/cursor at pause
- interruption committed vs false
- false-interruption duration
- resumed playback timestamp
- stale clauses discarded after commit
- interrupted clause metadata
- transcript latency for barge-in turns
- new first-clause latency after a committed interruption
- capture-preprocessor/AEC errors

Real hardware evaluation must measure:

- p50/p95 human-speech-start -> audible Vess pause latency
- real interruptions detected
- missed interruptions
- false interruptions per hour
- self-echo interruptions per hour
- successful false-interruption resumes
- stale clauses audibly played after committed interruption
- unheard complete clauses incorrectly recorded as delivered

## 15. Hard Invariants

The implementation is not acceptable unless all of these hold in deterministic tests:

1. A committed interruption makes every older generation stale.
2. No stale prepared clause may begin physical playback after commit.
3. Pausing alone does not cancel the active generation.
4. A false interruption can resume only the same still-current generation.
5. A newer generation prevents any old paused waveform from resuming.
6. `state.performance` is neutral while playback is physically paused.
7. The original performance cue returns only when resumed physical playback begins.
8. Raw self-echo/VAD energy alone cannot set `state.listening` when preprocessing has not accepted it as a candidate.
9. Fully generated but never completed clauses are never recorded as fully delivered speech.
10. Interrupted turns remain represented in short-term context instead of silently disappearing.
11. Interruption/cancellation operations are idempotent under duplicate events.
12. Playback, capture, synthesis, transcription, and rendering remain independent workers; the 30 FPS face loop never waits on barge-in logic.
13. Barage-in queues remain bounded; pausing playback cannot create unbounded synthesized-audio backlog.
14. Existing idle wake/follow-up behavior remains unchanged when barge-in is disabled.

## 16. Remote Test Strategy

All logic tests must run without microphone hardware, speakers, Ollama, Whisper models, Chatterbox, Kokoro, or CUDA.

Use fakes for:

- `AudioPlayer`
- capture preprocessor
- transcriber
- TTS engine
- LLM stream

Required deterministic scenarios include:

### Real interruption

```text
agent playback starts
human speech candidate reaches threshold
player pauses
utterance finishes
transcript is non-empty
old generation commits cancellation
new request is submitted
old queued/prepared speech never resumes
memory marks old turn interrupted
```

### False interruption

```text
agent playback starts
candidate reaches threshold
player pauses
no transcript arrives
false timeout fires
same waveform resumes
same generation remains current
memory remains an ordinary in-progress turn
```

### Superseded false interruption

```text
player pauses for candidate
another newer request arrives
candidate times out false
old waveform must not resume
```

### Interrupt during first clause

No completed assistant clause exists. Short-term memory still retains the user's prior request as an interrupted turn.

### Interrupt between clauses

Previously completed clauses remain delivered; prepared next clause is discarded on commit.

### Duplicate candidate

Two candidate notifications cause only one pause and one state transition.

### Race: commit while synthesis finishes

The newly synthesized stale waveform must fail freshness checks and never play.

### Race: shutdown while paused

Shutdown exits cleanly without resume or deadlock.

### Feature disabled

Current behavior remains unchanged.

## 17. Target-PC Acceptance

Remote CI can prove state-machine, cancellation, delivery-ledger, and queue correctness. It cannot prove acoustic quality.

Before enabling barge-in by default on the target machine:

1. choose and integrate the actual local echo-preprocessing backend
2. test Vess speaking at realistic speaker volume with no human speech for at least several minutes
3. verify self-echo interruptions remain acceptably near zero
4. test interruptions at multiple distances/angles and normal speaking volumes
5. measure p50/p95 pause latency
6. test short words, long interruptions, coughing/noise, and speech beginning immediately after Vess starts
7. confirm false candidates resume naturally
8. confirm Qwen, Whisper, TTS, preprocessing, and rendering coexist within CPU/VRAM limits
9. inspect event traces for stale playback and memory-delivery mistakes

Only then should `barge_in.enabled` become true by default.

- new `output/audio_player.py`
- `output/voice.py`
- `brain/llm.py`

- `state.py`
- `main.py`
- `config.json`

Tests should be added/updated around audio capture, playback, voice freshness, conversation freshness, short-term memory, and new turn-coordinator behavior.

Do not combine this implementation with long-term memory, proactive behavior, planner work, or TTS-engine benchmarking.

## References Informing the Design

- LiveKit voice-agent interruption handling uses separate interruption policy, configurable minimum speech duration, false-interruption detection, and resumable false interruptions.
- LiveKit also truncates conversational history around speech actually heard after interruption, supporting the distinction between generated text and delivered text.
- WebRTC AEC3 is designed around capture plus render-reference processing rather than simple raw VAD gating.
- python-sounddevice/PortAudio stream APIs expose immediate abort semantics, while normal stop semantics may wait for pending output buffers. The production player should use the stream-level mechanism appropriate for fast interruption.

These references inform the architecture but do not become runtime dependencies by themselves.
